### Fixed

- The dispatch harness's committed-message vet no longer reads a git failure as a clean answer. It asked `git cat-file -e`, which exits 128 both for a path absent from the commit's tree and for a ref git could not resolve, and the guard mapped every failure to "no message file committed" — so a genuine git failure was indistinguishable from a clean negative. The vet now asks `git ls-tree`, which exits 0 with empty output only for a path genuinely absent from a tree it read; every other failure is a named `git_failed` refusal that holds the push rather than a silent pass. The `dispatch_message_committed` refusal's remediation now also names the follow-on `dispatch_message_present` refusal its own `git rm --cached` and amend leave behind, and a test pins the `.gitignore` entry that keeps a broad `git add` from staging the message file.

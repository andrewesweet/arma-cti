# Fixed

- `just gated-paths` now measures both the changed-path scan and every approval binding from the merge-base of `HEAD` and `origin/main`, so a branch behind `main` is refused only for edits it made itself (#623). An approval the human records while the branch is behind names the branch's own delta — never a diff carrying a reversal of `main`'s edit — and carries through the clean rebase `just land` performs before gating. Three consequences are visible in the gate's own bytes: a branch whose gated edit already equals `main`'s tip content is refused `approval_missing`, where the previous tip-relative scan passed it — the merge-base shows the branch did change the path, and the human can now approve it; a recorded approval whose `change_id` no longer matches the current binding is named `not_carried=change_id_mismatch` in the refusal instead of being skipped silently; and a hunk header normalises to a bare `@@` with Git's funcname guess stripped, so the same textual change binds identically however `main` moves the file's other lines. That normalisation re-keys every earlier record whose diff hunks carried a funcname guess (hunks after a text line that looks like a name do): such an approval — including one recorded while the branch sat exactly on `main` — stops matching and the refusal names it, so one fresh approval is owed; hunks with no funcname guess bind exactly as before. An unreadable or unrelated `origin/main` remains a typed `gated_paths_unreadable` refusal.

# Fixed

- `just worktree done` (and `archive`) now write a teardown record into the worktree's git admin directory before every `git worktree remove`, and refuse to remove at all where the record cannot be written, so a removal never runs unrecorded. A removal that aborts part-way is the typed refusal `worktree_remove_failed`; a retry that finds the tree no longer clean under a record refuses `teardown_ambiguous` — the record proves a removal of this tree began and cannot prove whose the differences are, so the tool restores nothing and names the recovery (`git checkout -- .`, taken by the reader on the printed list, then the same command again) instead of running it (#632).
- `harness_finish`'s `commit_message_absent` refusal no longer asserts whose the differences are: a teardown record refuses `teardown_ambiguous` naming the reader-owned recovery, and without a record the text states both readings — the session's work to commit by hand under `never reset` (#105), or possible removal debris to stop and report — rather than instructing a commit (#632).

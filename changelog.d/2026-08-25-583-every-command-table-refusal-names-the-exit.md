### Fixed

- Every command-table refusal now names its exit. The confinement, recipe and table refusals — from the gate route and the standalone `just check-command-table` alike — carry the human's direct approval command with the live content_id where one is computable, and the standalone CLI's unreadable-repository refusal, which previously printed no `action=` line at all, names the repair instead, because no unreadable tree can produce the content_id the approval command needs. Where no issue-N worktree or dispatch environment names the issue, the refusal no longer prints an unrunnable `--issue <issue>` placeholder: it states that the human supplies the issue number the tool would not guess, and the standalone CLI refuses a worktree/dispatch issue disagreement by name instead of silently discarding it. Three rounds of hand-enumerating these exits each missed one, so a test now scans both tools' source and fails on any statement whose string literals spell `refusal=` without an `action=` companion before a return, raise or `sys.exit`. The scan sees literal and literal-concatenated markers only — a marker composed from variables at runtime is outside its sight — and the test states that limit rather than claiming a full enumeration.

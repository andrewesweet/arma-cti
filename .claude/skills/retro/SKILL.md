Subject is the **process**, not the code: commands, failure classes, gates, skills, conventions in `CLAUDE.md` and `.claude/skills/`. Code defects belong in issues, not here.

1. **Evidence sweep** — from this session (or the named phase): where did an agent fight the process? Wrong or missing `just` command, failure class that didn't fit, gate that blocked without value or was bypassed, skill step that didn't survive contact, convention nobody followed.
2. **File items** — a retro identifies, researches and **files backlog items as GitHub issues on this repository's tracker** — the same surface every other unit of work uses, so an item is dispatchable without transcription; **it lands nothing** — stated as the rule rather than as a list of surfaces, per ADR-0071 ruling 3, because a list left `docs/process-log.md`, `CONTEXT.md` and `docs/adr/` unprohibited and retros have landed all three. Each filed item names the surface it would change (`CLAUDE.md`, `.claude/skills/*`, `docs/agents/*` — **never** the global Matt Pocock skills, which are shared across projects), states the change concretely enough to implement, and **cites the run, issue or commit its finding came from**, so a reader can check it without a reviewer standing behind it. The prohibition rests on finding and implementing being different jobs: a retro that lands its own findings is the propose-and-approve shape forbidden everywhere else. It does not rest on the category's importance, which if anything argues the other way. Bias toward removal: current models degrade under over-prescription, so prefer filing the deletion of an instruction the model already follows over filing a new one, and prefer one short behavioural instruction over enumerating cases.
3. **Route to the gate** — all process changes are human-gated, and a retro reaches that gate through a filed item rather than through a diff of its own. Present the items; the human rules on them, and an implementing seat carries the approved ones under ADR-0071 ruling 4 like any other change. ADR-0013's standing authorisation still applies to the seats that implement, not to this one: a retro has nothing to record as a delegated decision because it applies nothing. State the current depth of the review queue in the retro report and the journal entry — the count of `grep -rl "^Reviewed-by-human: pending" docs/adr/` (anchored, per ADR-0013 — approved ADRs and prose now mention the unanchored string, which over-counted 6-for-1 at the fifteenth retro) — so its growth is visible each cycle; clearing it is the human's cadence to choose, surfacing its size is this step's job. The consolidated ready-for-human pile anchors on the standing pile issue (#217) — open by design — never on a ruling issue, which a ruling closes: the twenty-second's pile comment sat on #200 and went unfindable-by-label two hours later.
4. **Journal** — append to `docs/process-log.md`: date, trigger (phase/playtest/ad-hoc), findings, **items filed**, findings deliberately not filed. One entry per retro, terse. **The journal is the single named exception to step 2's prohibition, and it lands.** The reason: it records what the retro did rather than changing a rule the retro judged, so it carries none of the propose-and-approve hazard — a journal entry asserts no rule and gates nothing. A retro that filed its own record would leave no durable in-tree trace that it ran, with the evidence bank issue-side and nothing to read against the tree. It lands like any other change under ADR-0071 ruling 4: a reviewing instance, and a lander who may be the proposer — *"the lander executes `just land`; it decides nothing, and it may be the proposer"*. **Flagged, not silently overridden:** ADR-0071 ruling 3 ends *"never-alone does not apply to retros, because nothing lands"*, and this exception makes it apply to exactly one artefact per retro — a review round per cycle that the ruling assumed away. The remedy is an ADR amendment in the A1/A2 shape, or the human ruling the journal exempt from review; until one lands the conflict stands on the record rather than in a commit message.
5. **Status upgrades** — any process artefact marked `unproven` that survived real use unchanged: file the upgrade of its marker (`validated ×N`). File downgrades or amendments for ones that failed. **The same-edit clause restated for the filed item:** the `×N` and its appended exemplar must be named in **one** filed item, **and the landing that carries that item moves both in one commit** — the obligation binds the implementing seat, not only the filer, because filing and landing are now separate acts where they were once the same edit. — the count lagged the list in two consecutive retro commits, each caught only by the next retro reading the log, and splitting them across two items reproduces that lag by construction. **The convention-lands clause, likewise restated:** where a retro files a new convention, the same item names its first applied instance, **and the landing that carries that item moves both in one commit** — the obligation binds the implementing seat, not only the filer, for the same reason as the clause above — and, because retro-filed conventions routinely name `.claude/skills/*` while their applied instance sits elsewhere, this clause carries a **routing constraint**: #294 refuses a dispatched session any write under `.claude/`, so an item whose halves straddle it must be implemented from a session that is not dispatched.

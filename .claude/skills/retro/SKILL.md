This skill amends itself only through its own procedure.

Subject is the **process**, not the code: commands, failure classes, gates, skills, conventions in `CLAUDE.md` and `.claude/skills/`. Code defects belong in issues, not here.

1. **Evidence sweep** — from this session (or the named phase): where did an agent fight the process? Wrong or missing `just` command, failure class that didn't fit, gate that blocked without value or was bypassed, skill step that didn't survive contact, convention nobody followed.
2. **Propose diffs** — concrete edits to project-owned surfaces only: `CLAUDE.md`, `.claude/skills/*`, `docs/agents/*`. **Never** the global (Matt Pocock) skills — they are shared across projects. Each diff: one-line rationale grounded in evidence from step 1, not taste. Bias toward removal: current models degrade under over-prescription, so prefer deleting an instruction the model already follows by default over adding a new one, and prefer one short behavioural instruction over enumerating cases.
3. **Sign-off** — all process changes are human-gated. Present the diffs; apply only what is approved. When the session is unattended, ADR-0013's standing authorisation applies as it does to every other gate: record the applied batch as a delegated decision, `Reviewed-by-human: pending`, and the human approves at review (as they did on 2026-08-01 for the first four retros). State the current depth of that review queue in the retro report and the journal entry — the count of `grep -rl "^Reviewed-by-human: pending" docs/adr/` (anchored, per ADR-0013 — approved ADRs and prose now mention the unanchored string, which over-counted 6-for-1 at the fifteenth retro) — so its growth is visible each cycle; clearing it is the human's cadence to choose, surfacing its size is this step's job.
4. **Journal** — append to `docs/process-log.md`: date, trigger (phase/playtest/ad-hoc), findings, changes applied, changes rejected. One entry per retro, terse.
5. **Status upgrades** — any process artefact marked `unproven` that survived real use unchanged: propose upgrading its marker (`validated ×N`). Downgrade or amend ones that failed. The `×N` and its appended exemplar move in the same edit — the count lagged the list in two consecutive retro commits, each caught only by the next retro reading the log.

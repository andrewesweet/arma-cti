## 2026-07-30 — user-directed amendment: full wiki snapshot (not a retro)

The Phase 0 retro added `docs/reference/arma-wiki/` to *Read first* on the strength of a research failure; it held nine hand-picked pages, which is thin cover for "consult the wiki first". A full BIKI export became available and is now vendored: 6,690 pages, tier A + B plus the non-article namespaces. *Read first* gained the navigation an agent needs to use it — guessable paths, `MANIFEST.json` as the lookup, per-directory `INDEX.md` instead of listing a 2,672-file directory — and two traps worth naming. Game applicability is in each file's `// categories:` header and never in the wikitext, because BIKI generates categories from templates, so grepping page source for `Arma 3` finds nothing. And pre-Arma-3-only pages are excluded, so a miss is not proof the wiki lacks the page.

## 2026-07-30 — retro: Phase 0 spike (#2)

First real retro. Trigger: phase completion.

**Findings.** The dominant one is a research failure, not an execution failure: eleven configuration hypotheses were tested and eliminated over most of a day before the headless-client blocker turned out to be one sentence of first-party documentation ("Don't forget to set NAME property"). The wiki was Cloudflare-blocked from this environment throughout, so the source holding the answer was the one source not consulted. Secondary: the `just` command table listed recipes that did not exist and omitted every recipe that did; the failure-class table earned its keep when `infra_unavailable` fired on a stale daemon holding a port and correctly refused to be interpreted as a result; the lint-after-edit hook deferred on 2026-07-30 became decidable once latency was measured.

**Applied** (all human-approved): command-surface table replaced with the recipes that exist, with the acceptance tiers marked as Phase 1 work; `docs/reference/arma-wiki/` added to *Read first* with an instruction to consult it before experimenting on engine behaviour; failure-class table marked `validated ×1`; a port-collision line added to *Contract*, since the Arma tier shares this machine with the human's play sessions under WSL2 mirrored networking; `lint-after-edit.py` enabled for `.sqf`/`.cpp`/`.rs` (132 ms and 121 ms measured, against 20–56 ms for the hooks already running), advisory-only so `just check` remains the gate.

**Rejected / no change.** `block-no-verify.py` false-positived on a Bash call whose heredoc *contained* the blocked phrase as text; it fails safe and the workaround (use Edit/Write) is obvious, so no change. The Contract's "never extend a timeout to make a test pass" was briefly ambiguous when a harness timeout was extended to fix a harness race rather than to pass a test; judged not worth extra words. Python left out of the lint hook: `uv run ruff check` on one file costs 183 ms, almost entirely `uv run` resolving the environment.

**Defects fixed in passing.** `format-on-edit.py` ran `rustfmt --edition 2021` against an edition-2024 crate, so it wrote files `cargo fmt --check` then rejected — an auto-formatter that disagrees with the gate is worse than no formatter. `ruff` 0.16 formats Python inside Markdown, which would silently rewrite third-party code quoted verbatim in research documents; `docs/` is now excluded, and the general rule is that a formatter must never rewrite a quotation.

**Status.** `CLAUDE.md` failure classes: `unproven` → `validated ×1`. The rest of `CLAUDE.md` survived the phase unchanged apart from the amendments above. `playtest-brief`, `playtest-ingest` and `retro` remain `unproven` — `retro` has now had one use, this entry.

## 2026-07-30 — retro: ad-hoc, Phase 1 (#9-#12)

Trigger: user-directed, on discovering `toJSON`/`fromJSON`.

**Findings.** *Read first* told an agent to consult the wiki "before experimenting on engine behaviour". That is a narrower trigger than it reads: the expensive miss this phase was not an experiment but an assumption. SQF was assumed to have no JSON parser, so `tools/generate_manifest_sqf.py` and `tools/generate_command_sqf.py` were built to render authored data into SQF literals — while `toJSON`/`fromJSON` had been engine-native since 2.18 and the server runs 2.20. The wiki was consulted repeatedly and correctly this phase (`random` syntax 3, `getUserInfo`, `CfgFunctions`, `loadFile`), so the instruction works when it fires; it simply did not fire for "does this already exist". Same shape, second instance: `skipLobby = 1` — the fix that made the headed client join unattended — was documented all along and sat on a closed issue's eliminated list.

**Applied** (human-requested): *Read first* now says to check the wiki before experimenting on engine behaviour **and before writing your own version of anything the engine might already do**, with the generator as the second worked example beside Phase 0's lost day.

**Also applied, on sign-off.** A *Working style* line that an elimination holds only in the context it was tested in — `skipLobby` was written off against a server whose mission was not initialised, and against one that was, it worked first time. And the failure-class table goes `validated ×1` → `×2`: a deliberately emptied manifest produced `assertion_failed` in-world and the harness refused to pass rather than booting an empty world, which is the second time the table earned its keep.

**Issues raised rather than fixed here.** #22 (replace the generated-SQF pipeline with `loadFile` + `fromJSON`; flagged ADR-0012-adjacent), #21 (exercise the client-to-gateway leg, blocked by #18).

**Status.** `retro` has now had two uses and has not needed amending; still `unproven` pending a use that tests it rather than exercising it.

## 2026-07-31 — retro: ad-hoc, after #27

Trigger: user-directed, after the per-side Observation projection landed.

**Findings.** The dominant one is a convention nobody followed, including the agent that wrote the convention's last amendment. `CLAUDE.md` says to interact with the project through `just` only, and the Phase-1 in-world tier has no recipe — `just spike` runs the phase-0 measurement mission. So both #15 and #27 were verified in-world by calling `./spike/run.sh --hold` directly with five environment variables. For #27 that invocation was reconstructed by reading the script and a *leftover* `.spike-out/mission/cti.Stratis/harness.sqf` staged by the previous session — a file the harness rewrites every run, so the reconstruction was luck. Second half of the same gap: #27's probe lived in the session scratchpad, so the issue carries its output and not its source, and re-verifying would mean rewriting it. Secondary: `git push origin main` from an agent worktree was rejected non-fast-forward, because it pushes the local `main` branch the worktree is not on; the correct sequence was undocumented. `cargo` is not on `PATH` in a default shell here, so every gate call this session carried a manual `export`, knowledge that travelled by handoff document rather than by the repo. And `/grill-me` was missing from the workflow backbone despite having driven both major design decisions to date.

**Applied** (all human-approved): `CLAUDE.md` gains `/grill-me` in the workflow backbone, a *Commits* bullet giving the worktree landing sequence, and a command-table row for `just probe` — added with the recipe rather than ahead of it, since a table listing recipes that do not exist is the defect the Phase 0 retro fixed. `.claude/skills/retro` goes `unproven` → `validated ×3`.

**Fixed rather than deferred** (#29, #30, both closed here): `just probe [file] [hold]` wraps the Phase-1 tier; `spike/probes/` holds probes in the repo, so the evidence a verification rests on outlives the session that wrote it; the justfile puts `~/.cargo/bin` on `PATH`. Building them turned up a false-green the retro had not: hold mode read its verdict when the hold window closed, so a probe still working at that moment reported `HOLD-COMPLETE` off a log it had not finished writing. `CTI_HARNESS_AWAIT` now waits for the probe's own completion line, with `FAIL` ending the wait too so an assertion is classified as one rather than timing out. Proven by running the #27 probe under a 60-second hold it outlives.

**Rejected / no change.** A rule about preserving probe source alongside its evidence: real, but it dissolves once `spike/probes/` exists, and a rule duplicating a tool is the over-prescription this skill warns against. A rule about editor diagnostics: `ty` in-editor contradicted the gate repeatedly this session (`EconomyTable has no attribute capture_seconds` and two others) while `just check` passed, and the gate was treated as authoritative without needing to be told — *"The gates above are this project's verification"* already covers it.

**Status.** `.claude/skills/retro`: `unproven` → `validated ×3`. Failure classes stay `validated ×2` — `assertion_failed` was wired into the #27 probe but never fired, so nothing new was earned. `playtest-brief` and `playtest-ingest` remain `unproven` and unused.

## 2026-08-01 — retro: scheduled, five issues (#28, #16, #17, #12, #22)

Trigger: five issues closed since the last retro. Also landed since: ADR-0013–0018, `docs/regression-tier.md`; #31 raised.

**Findings.**

- *Closure lagged landing, and the #12 audit earned itself once.* Three of the five sat closed-in-fact but open-in-record for a session, and #12 was nearly closed off commit titles. The read-only audit found criterion 8 unmet — but the evidence trail shows the pivot (callback-push → poll-and-ack) was *flagged* in #12's original delivery comment; what was missing was a decision record, which ADR-0018 then supplied. So the audit is not made a standing requirement. Instead the discipline that made #16/#17/#22/#28 auditable at a glance — close in the landing session, per-criterion evidence, supersessions recorded not narrated — is codified in `docs/agents/issue-tracker.md`, with the full audit required only when inheriting an issue whose work landed in an earlier session.
- *The ADR-number collision's fix worked first time.* #22 claimed ADR-0017 by issue comment while ADR-0018 landed concurrently; no second collision. The claim-by-comment rule *is* the structural fix — a reservation protocol over a shared namespace — so no deeper change; rule marked `validated ×1`.
- *The tier serialisation finding is a sequencing one.* The corpus grew 4 → 7 probes while #23 (the runner, lock, evidence dirs) stayed unbuilt, and three independent issues queued on one hand-driven tier. Recommended on #23: build it before further in-world feature work. Not made a CLAUDE.md rule — it is a scheduling call, and one instance.
- *Conventions designed but not applied, second instance of the pattern.* ADR-0016's `probe:`/`issues:`/`window:` header existed on no probe. Fixed here: all seven probes now carry the block, plus `// expect: assertion_failed` on `manifest-missing` — the red-by-design probe ADR-0016's "corpus gated green" definition did not anticipate; the design doc now specifies `expect:`. CLAUDE.md gains one working-style line: land a convention with its first applied instance. (The 420-vs-300 window discrepancy was already fixed on main before this retro.)
- *The six delegated ADRs are genuine decisions, not rationalisations* — each weighs rejected alternatives, and five of six state overturning evidence; they ratify built work and say so, which is what a sign-off on a flagged judgement call is. Two audit gaps fixed under ADR-0019: the marker set could not answer "which have I since reviewed" (field block gains `Reviewed-by-human: pending`, flipped only by the human; 0013–0018 retrofitted), and ADR-0015 stated no overturning evidence (retrofitted).
- *The probe corpus is load-bearing, not decorative.* This phase it found: three `targetsQuery` engine facts none of which a unit test could reach (#28), `Roster.reconcile` deleting Squads in flight, the desync loader gifting four Objectives (caught twice, two guards), travel scored in hops not metres, the harness's hold-mode false-green and its hard-coded 180 s cap, and it verified the `loadFile`-in-PBO fact ADR-0017 stands on.
- *`just check`/`just unit` caught one thing on record this phase*: `schema_stale` fired mid-session on #22 against a stale export. Every other defect lived at the engine boundary. The unit tier's job this phase was containment (283 tests holding determinism, no-overspend, isolation), not discovery — which is more weight on building #23, not less on the gates.

**Applied** (recorded as delegated decisions under ADR-0019, `Reviewed-by-human: pending`): closing-discipline section in `docs/agents/issue-tracker.md`; probe header blocks on all seven probes and the `expect:` extension in `docs/regression-tier.md`; ADR-0013 convention amended (fourth field line, overturning-evidence requirement); ADR-0014–0018 retrofitted with the field; ADR-0015 retrofitted with overturning evidence; CLAUDE.md marker bumps and the convention-lands-with-instance line.

**Proposed, not applied — for the human.** Two edits to `.claude/skills/retro` were blocked at the permission layer, treated as the gate speaking: (1) status `validated ×3` → `×4` (fourth use; whether it counts as "no amendment needed" depends on (2)); (2) a step-3 sentence saying that in an unattended session ADR-0013's standing authorisation may discharge the sign-off gate via a delegated ADR — this retro acted on that reading, and the skill should either say it or the reading should be repudiated.

**Rejected / no change.** A standing requirement to audit every issue at close (the discipline above makes it the exception, and ~70k tokens is a price to pay on inheritance, not on every close). A CLAUDE.md rule ordering capability work ahead of feature work (one instance, scheduling not process). Cutting `playtest-brief`/`playtest-ingest`: still `unproven` and unused after four phases, but for a structural reason — nothing a human can play exists yet (no map UI, no win conditions), so disuse is not evidence of failure. Tripwire instead: if the first play session happens without `playtest-brief` having authored its brief, cut both at the following retro.

**Status.** Failure classes `validated ×2` → `×3` (#22: `infra_unavailable` refused a mis-staged failure as a result; the properly reached guard classified `assertion_failed`). Probe-window rule `validated ×1` → `×2` (#17: the harness's own 180 s cap was fixed by honouring the subject-sized window, not by extending anything). ADR-claiming rule → `validated ×1`. `retro` `×3` → `×4` proposed above. `playtest-brief`/`playtest-ingest` stay `unproven`, tripwired.

## 2026-08-01 — retro: scheduled, five issues (#31, #23, #32, #34, #33)

Trigger: five issues closed since the same-day retro above. ADR-0020 and 0021 landed; #32–#35 raised, three closed. Amendments recorded under ADR-0022 (`Reviewed-by-human: pending`), claimed by comment on #35 while a #35 agent lands concurrently.

**Findings.**

- *A session limit killed two agents mid-flight, and the process had no words for it.* One died mid-Arma-run with uncommitted work, a dead server, and a half-written evidence directory. Everything designed held without being asked: the tier's `flock` freed itself on holder death — chosen for exactly this, first exercised the day it shipped — and both agents resumed cleanly from their worktrees' last commit plus `git status`. What was improvised was the orchestrator's reading of the leftovers, so that reading is now written: a dead run's evidence carries no `verdict.json` and is not a result; its leftover world is stale state to clear, never context to inherit (CLAUDE.md lock paragraph, ADR-0022). A worktree-resumption runbook was declined — both resumptions worked from what worktrees already afford, and a procedure would prescribe the default.
- *The regression tier changed behaviour within hours of landing, and full-corpus-per-issue is the right default at this size.* #32 was gated by `just regress` instead of a bespoke probe and the run closed a corpus gap in place (no probe asserted an Order carries a Place — the one failure mode of the rename no unit test could see); #33 ran 9/9. Cost is measured, not felt: ~1.5–2 min of wall per probe including bring-up (12 m 38 s / 13 m 10 s / 12 m 56 s at 8 probes, ~16 m at 9). The design already made selection a fable-session call on corpus growth; this session made it a number — first full green pass over 30 minutes builds `issues:`-header selection before the next probe lands. Tracked as #36; issue-class subsets declined again, for the design's own reason (the expensive failures are the unselected kind).
- *Two placeholders landed as sign-off-ready surfaces without a rule saying how.* #34 measured its `decapitation` 8.0 across 200 seeds and reported the behavioural window (7.27, 8.87) with the thinnest margin (0.11); #33 chose the simplest demolition mechanism and named the passed-over alternatives in the file header. Both are what a flagged judgement call should look like, and both happened unprompted — which is the evidence *against* requiring the pattern. "Measured window + thinnest margin" is also surface-specific: #33's fixed 90 s has no seed window to measure. Recorded here as exemplars; no rule.
- *Parallel dispatch with a ground partition worked, and stays uncodified.* #33 and #34 ran concurrently with do-not-touch lists; the predicted probe collision did not materialise; #34 yielded the tier by partition without ever contending the lock. One clean instance of a scheduling call, not process.
- *#31 closed as a decision ticket — ADR + CONTEXT terms + four implementation issues in dependency order, no code — and three implementing agents needed zero clarifying questions.* Named as a pattern in `docs/agents/issue-tracker.md` (ungated surface), with the flag that triggers one: a build ticket saying a decision is "not the scorer's to route around".
- *The lock's `infra_unavailable`-on-held fired only deliberately* (#23's demonstration, including bounded `--wait`); in anger, the holder-death case fired instead and produced the opposite of a stale stop — a free tier. No agent report reads a held lock as a result.
- *Building the runner found the harness had been mistyping every in-world failure* as `assertion_failed`, including ones the world had typed `timeout` or `oracle_disagreement` — latent in every hand run to date, and surfaced because the table's required-response column makes a wrong class a harness bug. That is the failure-class table's fourth earn.

**Applied** (under ADR-0022): the dead-holder sentence in CLAUDE.md's lock paragraph and the matching validation note in `docs/regression-tier.md`; the 30-minute selection tripwire in `docs/regression-tier.md` §Cost control (+ #36); the decision-ticket section in `docs/agents/issue-tracker.md`; marker bumps below.

**Rejected / no change.** Requiring the measured-window pattern for placeholders (over-prescription; both agents did it unprompted, and the pattern is surface-specific). A worktree-death recovery runbook (the tools already afford it). Codifying parallel-dispatch partitioning (one instance; scheduling, not process). Issue-class regress subsets (cost measured and cheap; the tripwire owns the future).

**Pending for the human, not retried.** The previous retro's two blocked `.claude/skills/retro/SKILL.md` edits — the status `×4` bump and the standing-authorisation sentence for step 3 — remain proposed and unanswered. This retro again acted on the standing-authorisation reading (ADR-0022); the skill still does not say it may.

**Status.** Failure classes `×3` → `×4` (#23: the mistyping fix — the harness now believes the line's own class). Probe-window rule `×2` → `×3` (#33: two effects on separate pump turns; fixed by waiting on the pair, window unmoved). ADR-claiming rule `×1` → `×2` (#23's 0020 → 0021 renumber on rebase, exactly as prescribed). Convention-lands-with-first-instance → `validated ×1` (#23 landed row, lock, and evidence conventions with the recipe). `retro` file marker stays `×3` with `×5` now the honest pending proposal (fifth use, no amendment needed by either of the last two). `playtest-brief`/`playtest-ingest` unchanged, still tripwired on the first play session.

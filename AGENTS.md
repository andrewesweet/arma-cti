# arma-cti

Personal Arma 3 Capture the Island scenario, developed primarily by autonomous agents with maximal automated testing. Session-based persistent campaign; player as Commander or squad leader.

> **Process status: written 2026-07-30 before first practical use; since exercised by twenty-seven retros.** A rule's earned standing is its own `validated ×N` marker; a rule without one is still a hypothesis until a retro validates it. Propose changes only via `/retro`; never drift silently. Audit trail: `docs/process-log.md`.

## Read first

- `CONTEXT.md` — domain glossary. Use its vocabulary exactly; respect the _Avoid_ lists.
- `docs/adr/` — binding decisions. Flag conflicts explicitly; never silently override.
- `docs/mvp-scope.md` — what is in and out of the MVP.
- `docs/reference/arma-wiki/` — vendored Bohemia wiki, now the whole of it (6,690 pages); the live one is Cloudflare-blocked from here. Check it before experimenting on engine behaviour, and before writing your own version of anything the engine might already do. A day of Phase 0 went to rediscovering one documented sentence; Phase 1 built a code generator around a JSON parser the engine had shipped two versions earlier.
  - Paths are guessable: `commands/setDamage.wiki`, `functions/BIS_fnc_spawnGroup.wiki`, plus `topics/`, `classnames/`, `templates/`. `MANIFEST.json` maps every title to its path and carries the redirect aliases. Read a directory's `INDEX.md` rather than listing it — `commands/` alone holds 2,672 files.
  - Which games a page applies to lives in its `// categories:` header, never in the wikitext: BIKI generates categories from templates, so grepping page source for `Arma 3` finds nothing.
  - Pages tagged only for pre-Arma-3 titles are excluded, so a miss is not proof the wiki lacks the page.

## Model roles

Ratified (model, effort) ↔ task mapping (human decision, 2026-08-04, in the orchestrator session; replaces the two-role list this section carried since 2026-07-30):

- **fable[1m], effort high** — retros, anything touching ADRs, CONTEXT.md, schema semantics, or process docs; and, by exception, diagnosis-shaped fixes where no gate catches a subtly wrong answer (the #181 shape: a planner defect whose plausible wrong fix would also have gone green). Defer structural decisions to a fable session rather than improvising.
- **opus[1m], effort high** — implementation and review, the default opus tier: corpus-gated features, planner work, prototypes, small-fry batches. During #242's ten-cycle pre-registered trial, the orchestration standing loop also runs here and dispatches fable for retros; ADR, CONTEXT.md and schema semantics; retro evidence banking; and the #181-shaped diagnosis call. Human decision sessions run at opus xhigh (existing practice). The default was lowered from xhigh on 2026-08-05, and #220's ruling records the rationale after the fact: effort is an output-volume multiplier, output is what this plan meters (33.10 points of a five-hour window per Mtok, against under 0.0096 for a cache write), so this is plausibly the largest single spend intervention the project has made — and one that registers as approximately nothing in input-equivalents, which is why it was never ranked as a saving.
- **opus[1m], effort xhigh** — reserved for where it is truly needed (human decision, 2026-08-05): hard diagnosis, a wide design surface, or a prior high-effort attempt that failed review; name the reason when dispatching at this tier. Also the **human interface**, separated from the orchestration standing loop by the human's ruling of 2026-08-06 on #242: rulings intake, status, observations on existing work, raising issues. That seat is reached as `/interlocutor` — a slash command whose own frontmatter carries the pair, so the human talks to it in their own session rather than dispatching it (ADR-0068, #255). A single invocation buys one turn: for a conversation, set the session with `/model opus` and `/effort xhigh`, both of which take an argument from Remote Control.
- **sonnet, effort medium** — mechanical one-commit executions: ruling transcriptions, CHANGELOG/docs sweeps, worktree hygiene.
- **haiku, effort low** — read-only reconnaissance, search, triage sweeps.

Mechanism, and why this section exists: the Agent tool carries no effort parameter, and a subagent silently inherits its dispatcher's model unless overridden — which is how every implementation agent of 2026-08-04 ran on fable and consumed the bulk of a weekly budget. Effort becomes real only through a definition file, so the enforcing seats live in `.claude/agents/` (`cti-implementer` opus/high, `cti-implementer-xhigh` opus/xhigh reserved, `cti-interlocutor` opus/xhigh human interface, `cti-mechanical` sonnet/medium, `cti-recon` haiku/low read-only); dispatch through them rather than by naming a bare model. Skill frontmatter carries the same `model`/`effort` pair for a seat the human invokes rather than dispatches. Both surfaces fail **open** — a level that does not exist, or a key that has drifted below the top level, leaves the seat at the session's tier and says nothing — so `just check-seats` asserts the pair rather than trusting it (ADR-0068). The harness enumerates `.claude/agents/` once, at session start, so a seat definition written mid-session is not dispatchable in that session (#219 ran both its stand-ins as prompt-prefixed existing seats for exactly this reason); a seat that must persist lands on `main` through this mapping's sign-off, never as a file in a session's tree. Sessions hand over via `/handoff`.

A dispatch names a **profile** — one opaque `(lane, model, effort)` token from `tools/dispatch.py`'s registry — not a model and an effort chosen separately. Profiles are not commensurable across lanes: GLM Max and Opus high are not the same quantity and the mapping is not monotonic, so no cross-provider effort scale exists and none should be inferred (ADR-0061 Decision 5). Measured rather than assumed on the z.ai lane: the endpoint ignores `thinking.budget_tokens`, so all five Claude Code effort levels are one configuration there (#225).

Work may leave Claude iff a mechanical gate catches a wrong answer (ADR-0061 Decision 2). Eligible on a foreign lane: **implementer, mechanical, recon, review**. Barred: **fable** and **orchestrator**, and the #181 shape — a diagnosis whose plausible wrong fix would also have gone green. `tools/dispatch.py`'s `SEATS` is the enforcing copy; this list follows it.

Retros are approved on nine profiles, enumerated by the human on 2026-08-09 (#300): `codex-sol-xhigh` and `codex-sol-max` (Sol 5.6 xhigh and max), `opus-high`, `opus-xhigh` and `opus-max`, and `fable-medium`, `fable-high`, `fable-xhigh` and `fable-max`. Only the two `codex` profiles need an allowance — on `claude-native` the `fable` seat is already permitted — so `tools/dispatch.py` suspends ADR-0061 Decision 2 for `fable` on `codex`/`codex-sol-xhigh` and `codex`/`codex-sol-max`, standing, and refuses every other fable-on-foreign route including `codex-sol-high`. "Or above" is not a comparison the code makes: profiles are opaque `(lane, model, effort)` tokens and no cross-provider effort scale exists (ADR-0061 decision 5), so a level joins the list by being named. Nothing tells the dispatcher that an issue is a retro, so the list beyond those two routes is honoured by whoever dispatches, not enforced.

A lane's authority is the enforcement it demonstrably runs, proven by the hook-parity suite in pytest — never what its provider claims. The z.ai lane's first live run executed the host's global hooks and never entered this repository's `.claude/hooks/`; that gap is what the suite closes (#225).

This table sits on a human-gated file, so where an agent cannot land the row with the recipe, the row follows through the sign-off gate — human approval or an ADR-0013 record — rather than lagging silently (#198/#199 proposed their rows; ADR-0057 landed them).

Lane environments are assembled per invocation by `just dispatch` and exported nowhere: `ANTHROPIC_BASE_URL` set globally redirects every Claude Code session on this box, the orchestrator's included. Credentials come from `~/.arma-cti/credentials.env` at mode 0600, by environment only — never on argv, so never in `ps` — and a dispatch record names the key it used, never its value. A foreign lane refuses the seats no mechanical gate covers. A lane that cannot be reached — no credentials file, no key, no worktree — is `infra_unavailable` and is not a result. Evidence lands in `~/.arma-cti/dispatches/<id>/`, outside every worktree.

A profile **on probation is dispatchable**: the ten-issue record the admission bar judges accrues only as the lane runs, so refusing probation would make the bar unclearable. What `just dispatch` refuses is the far end — a profile that has spent both attempts. `just admission reset --force` is the human's act and never an agent's, because running it converts the ruling's two attempts into unlimited ones. That refusal deliberately carries **no** failure class: it says nothing about a provider and nothing about the code under test, and a class exists to tell a reader what to do with a verdict rather than with a refusal to produce one.

`just watch-report` leads with the lane breakers (#226): one line per lane that is not dispatchable, and silence for every lane that is. The line is a verdict — `dispatch=refused`, a failure class, and a reset time where the provider published one — never three percentages, per #209's rule that where a rule-table already decides, an agent is not handed numbers to reason about.

`docs/multi-provider-dispatch.md` carries the lane and profile model, per-invocation environment assembly, the worktree assertion and the breaker's derivation; `docs/review-dispatch.md` carries the review seat's dispatch shape, its claims-cite-code output contract and its routing; `docs/telemetry-ledger.md` carries the ledger's retention and its view-not-writer reasoning. The rules an agent must not get wrong in the moment stay here.

`--issues` selects on what motivated a probe, not on what a change touched, so it is for revisiting an earlier issue's ground — never for gating your own issue, where it would select only the probes you just wrote. A filter matching no probe is an error, not a pass. The tier is a **pool of slots** (ADR-0028, #47): a slot is a port block, a daemon, a server install, an engine profile and a world that agree, and each has its own `flock` at `~/.arma-cti/slots/N.lock`. Slot 0 is the tier as it always was — `~/arma3server` on 2402–2406 — so `just probe`, `just spike` take that lock and a pool run and a hand run exclude each other where they would collide. Fewer slots free than asked for is a smaller pool, not a failure; **no** slot free is `infra_unavailable` with every holder's metadata and is **not a result** — do not interpret it, and do not retry into it blindly; `--wait <secs>` bounds a queue. An agent that dies holding a slot releases its lock by itself (kernel `flock`; proven on the first holder death, 2026-08-01): its half-written evidence carries no `verdict.json` and is **not a result**, and any server, daemon, or staged world it left behind is stale state for that slot's *next* holder to clear on acquire, never context to inherit (ADR-0022). Every per-slot value names a consumer, because **a slot boundary is only real where something reads it** — #44's first two-slot run had isolated ports, dirs, installs and daemons and the two worlds still merged on a `CTI_DAEMON_ADDR` nobody set, and the run not asserting on it went green. Evidence lands under `~/.arma-cti/runs/`, outside every worktree, and the durable record is the verdict plus evidence path plus SHA quoted into the issue the run gated. Full design: `docs/regression-tier.md`.

`hold` is the probe's window in seconds, default 150. Raise it when the probe's **subject** genuinely takes longer — `spike/probes/contact-decay.sqf` runs at 300 because no shorter window can contain the 120 s of knowledge decay it measures. State the reason in the probe's own header, which is authoritative — this table is not. This is not licence against the `timeout` row above: sizing the window to what is being measured is allowed, extending it until a flaky probe passes is the thing that row forbids. A probe that fails at 150 and passes at 300 without its subject having grown that long is a synchronisation bug, and the fix is in the probe. The same rule one level up governs what a probe asserts: bet on the decision the code under test owns, never on a world-owned outcome such as a firefight — #38 burned seven runs before `massed-assault` stopped gating on one; the worked example is in `docs/regression-tier.md`. Its sibling: assert that your staging took effect, because the world can refuse it silently — a probe cannot stub a `cti_fnc_` (the Functions Library `compileFinal`s them all), and `schema-stale`'s first draft went on testing the real function while reading as if it had tested a stub, caught only because the assertions were on outcomes (#80; write-up in the same doc). _(validated ×8 — newest five exemplars, the rest pruned to docs/process-log.md per #201: #35: a Squad teleported to the enemy Base at t=40 met three Squads the real Campaign would long since have marched away — the fix restored the conditions the shortened march stands in for, not more time. #43: converting fixed settles to event-driven exits left `two-commanders` alone, because its soak carries #17's measured drain extremum and an extremum shrinks with its window — the rule's own reasoning, applied as a reason not to shorten. #46: the full conversion pass kept that floor a second time and turned the soak's end-of-window absence claims into 2 s watchers — strictly stronger claims over the same unmoved window. #104: the recall's 480 s window is seven phase deadlines' arithmetic, stated in the header, and the board under it was proven before the window was trusted — the real planner run offline over the exact staged sequence across thirty seeds, so the probe bets on a decision the staging demonstrably forces rather than one it hopes for; ## Failure classes

Every harness verdict carries a `class`. Read it before anything else. ## Contract

**Always**: run `just check` + `just unit` after every edit; read the failure bundle before modifying code when one exists.

**Never**: edit an acceptance spec to make it pass; add a sleep, retry, or timeout extension to make a test pass; introduce a bare `random` or bare `sleep` in SQF (seeded PRNG and the `cti_fnc_everyInterval` scheduler adapter only — deliberately not CBA, for the dependency reasoning its header records; #85); call `setGroupOwner` outside `spike/desync-load.sqf` — Squads are never transferred off the server, and `tools/check_sqf_bans.py` enforces it (ADR-0039, human decision on #117; the tool moved out of the shipped addon in ADR-0045); treat `infra_unavailable` as a result.

**Never** `export ANTHROPIC_BASE_URL` (or any lane variable) into a shell, a profile, or `~/.claude/settings.json` — lane environments are assembled per invocation by `just dispatch` and nowhere else.

**Never** extend, invent or guess a breaker's wait. A lane reopens at a boundary its provider published, on evidence that it is serving again, or by a human's hand — never on a timer this project chose. (The measured reason: LiteLLM's five-second reactive cooldown against five-hour windows is what disqualified it as this breaker, `docs/research/multi-provider-routing-substrates.md` §3.2.)

The Arma tier shares this machine with the human's play sessions, and WSL2 mirrored networking shares the port space with Windows. The tier may allocate within **[2400, 3000)** (human decision, 2026-08-02, on #47) and must never take 2302–2306. Slot scheme: `2402 + 100×N` per ADR-0028, so slot ports are predictable and Steam's derived +1/+2 stay inside the slot's stride.

## Toolchains

Strictness principle: every tool runs in its strictest practical mode and warnings are errors. A suppression (`# noqa`, `#[allow]`, ignore entry) requires an inline comment justifying it.

- **Python** (daemon + planner in `src/cti_daemon/`, tests in `tests/`): managed by `uv` (locked deps, pinned interpreter; run everything via `uv run`). `ruff` for lint + format; `ty` (Astral) for type checking; `pytest` + `hypothesis`; `coverage.py`; `tools/mutation_smoke.py`, a bespoke bounded mutator over each landing's new test modules rather than a general-purpose engine — `mutmut` and `cosmic-ray` were both measured against it and neither qualified (ADR-0064, #281).
- **Rust** (shim only, `extension/`): toolchain pinned in `rust-toolchain.toml`; `cargo clippy -- -D warnings` and `rustfmt --check` in `just check`; `cargo-xwin` for the Windows `.dll`.
- **SQF** (`addons/`, `missions/`): HEMTT lints are the primary static tier (SQF-VM optional — see docs/research/arma-toolchain.md).
- **Bash** (harness orchestration only): the shell keeps the seams where it is the subject — launching and holding processes, `flock`, environment assembly, signals, `timeout`, flag files between workers. Non-trivial logic — a decision ladder, aggregation, a structured format, arithmetic past a counter — lands in Python under pytest, invoked through a `timeout`-bounded `uv run` and checked at its site; logic already in bash past that line migrates one seam per issue with its tests, never as a big-bang rewrite of the tier that runs the corpus (ADR-0049, #171; inventory on #171. Three conversions landed clean and regression-free — `tools/probe_verdict.py` #171, `tools/host_guard_verdict.py` #161, `tools/pool_merge.py` #185 — each red-first pins into one Python home with every caller failing closed, and #185 routed the class-table residue to #92/#147 at the `CLASS_RANK` comment rather than leaving a parallel table).

Repo hooks (`.claude/hooks/`, wired in `.claude/settings.json`) enforce mechanically: no edits to generated files or acceptance specs (`tests/specs/`), no `git commit --no-verify`, auto-format on edit; and, since #205/#207, no foreground wait of 240 s or more inside a subagent's turn and no `Read` whose window would deliver 40,000+ characters — both fail closed, both denials name their remedy. A denial on a gated surface means propose, don't work around; a token-economy denial means take the remedy it names. Hooks run from each session's own worktree copy of `.claude/hooks/`, so a hook fix landed on `main` governs a session only once that session's worktree rebases: a denial the landed fix should have prevented means a stale copy, not a failed fix (#120's fourth false positive fired exactly this way, during the fix itself).

## Commits, changelog, versioning (ADR-0010)

- Commit messages follow Conventional Commits 1.0.0 (`feat`, `fix`, `docs`, `test`, `refactor`, `perf`, `build`, `chore`, `ci`; optional scope; `BREAKING CHANGE:` footer or `!` for breaking). A `commit-msg` hook (`cog verify`) rejects everything else; if the hook is missing on a fresh clone, run `cog install-hook commit-msg`.
- Any commit with user-visible effect updates the `[Unreleased]` section of `CHANGELOG.md` in the same commit (Keep a Changelog 1.1.0 categories: Added/Changed/Deprecated/Removed/Fixed/Security). The changelog is curated for humans — never paste commit logs into it.
- Releases: `cog bump --auto` derives the SemVer 2.0.0 bump and tags `vX.Y.Z`. `0.y.z` until MVP scope is fully playable.
- Landing from an agent worktree: `just land`, which runs the protocol and refuses by name (#213). It re-gates after the rebase — no flag skips that — and when sandboxing blocks the fast-forward of the main checkout it exits non-zero with `merge_command=` naming the exact command for the orchestrator, because a stale main checkout is where ADR-0042's stale-hook window comes from (#130).

## Working style

- **A turn does not block for five minutes, and which seat it is decides what happens next. An agent that has ended cannot stall** — that is the rule's basis, and it is what survived #218's measurement of the cache arithmetic it used to rest on (human rulings 2026-08-05 on #200, #204 and #218; the retired figures are kept as history in `docs/research/token-efficiency.md` §2). The evidence is the stall record: 226 measured subagent stalls, eleven of them caught only by an external watcher (`docs/agents/recovery.md`), and the #168 agent stalling twice in one evening at the identical point. **In a subagent**, foreseeably long work is dispatched detached and the agent then *ends*: it commits, arms `just watch`, writes a handoff per `docs/agents/handoff.md`, and stops there. The value is entirely in the ending — being woken later is not the cheap half of it. **In the orchestrator**, waiting is what the seat is for, so the orchestrator holds the wait. Foreseeable is not an in-the-moment judgement: it is the measured denial list in `.claude/hooks/deny-subagent-waits.py`, and a gate that overruns an expectation off that list is bad luck, not a breach — carry on. That list reaches the unfiltered regression corpus, so the detached path is the only way a subagent can satisfy the `just regress` row's full corpus, no filter. **A wait that genuinely cannot be decomposed has one sanctioned fallback: dispatch it as a session** — `just dispatch --lane claude-native` — **with `just watch` armed at dispatch and the result read from the ledger** (#218's ruling, decision 1). A dispatched session is detached and nothing wakes anyone when it ends, so a session started and forgotten is not the sanctioned shape: the monitoring burden moves, it does not vanish. Keepalive turns stay unsanctioned, on the same ground rather than on cost — a keepalive exists to hold a turn open across something the agent is not doing, which is the stall shape wearing a timer, and with the fallback in place it is redundant besides. **The exception list is empty**, and grows only at a retro, never by an agent's judgement in the moment — the 226 stalls were all agents that believed staying was fine. None of this is a licence to shorten a gate: the gate finishes sooner running exactly the same assertions. A dispatched session is single-shot: it has no second turn for a background completion or a question. Run awaited work in the foreground; decide routine ambiguities, act, and record the reasoning. If a choice is genuinely the human's, finish the unambiguous part and state exactly what remains and why.
- **Reading a finished verdict is not seat-gated, and what qualifies a reader is the paste rule: quote `just verdict`'s rendered body verbatim; never retype the SHA or the evidence path.** #219's A/B settled it (human ruling 2026-08-05): across 40 scored readings over 8 replayed pools weighted toward reds and not-a-result stops, every arm at every price read every worst class correctly, refused every `infra_unavailable`, and would have landed on no red — and all four failures were the same mechanical act of retyping the tool's output instead of pasting it, once producing a plausible evidence path that resolves to nothing, which is worse than none. Its cleanest comparison is two arms on the same model, effort and tools differing only in their instructions, three failures against none, which is why no fifth seat was ratified. Carry the rule into any briefing that dispatches a verdict reader. The orchestrator reading is not deprecated; `cti-recon` is read-only by definition and may read and report a verdict but never be the seat that lands or dispatches. Whether a dispatch names the right issue, branch and SHA stays with whoever wrote the handoff, not with the reader — a design choice rather than a measured-safe one, and the first thing to re-open if a false gate record ever lands on the wrong issue.
- Deliver what was asked, at the scope intended. Make routine judgement calls yourself; check in only when different readings of the request would lead to materially different work. If the request seems mistaken or a better approach exists, say so in a sentence and continue as asked.
- The gates above are this project's verification. Do not add further verification passes, re-checks, or verifier subagents beyond them. Re-based by the human's ruling on #220: this was a quality rule and is now also a first-order cost rule, because an extra pass is pure generation and generation is the act this plan meters — on this plan the project is charged for what it writes, not for what it reads.
- Two providers over one diff is **one review pass with two lenses**, not a second pass. The no-further-verification rule above bars adding a *pass*; a second lens adds none — both lenses report into the same review, and a foreign lens may equally run alone. Provider diversity is the point (ADR-0061 Decision 3): one family's blind spots are not another's.
- Delegate to subagents only for sizeable, genuinely independent tracks of work. Do not delegate what you can finish yourself in a handful of tool calls, and never to double-check your own work.
- Ground progress claims in tool results from this session: quote failing output, name skipped steps, mark unverified work as unverified.
- An agent watching a run watches it from inside its turn: nothing an agent arms outlives its turn, so a turn that ends "standing by", "monitor armed", or with a gate run parked in the background is a wait nothing will wake. (First instance 2026-08-02; then the #168 agent stalled twice in one evening at the identical point — a background `just unit` finished with nobody to read it, its completed fix committed but unlanded — each stall caught only by the orchestrator's external watcher and cleared only by a prod naming what had finished.) `just watch` (#198) is the sanctioned detachment, not a licence against this: the watcher outlives the turn because its finding lands at the top of a later turn the orchestrator was taking anyway — armed at dispatch, read via `just watch-report`, never waited on from inside a turn.
- Before any work in a worktree, verify it is exclusively yours — clean `git status`, and no foreign uncommitted files appearing during the run — and commit early and often; foreign files mean stop and report, never reset. Standing mitigation while #105 is open: worktree assignment handed two agents one tree five times in one evening (2026-08-02), a routine reset-to-origin at task start is what turns the collision into destroyed work, and the pre-flight prevented a repeat on its first firing.
- Measure before building: a rule proposed on cost or threshold grounds is checked by running the measurement, not settled by intuition. Declined twice, by the twenty-third and twenty-fourth retros, on #209's cache-cost arithmetic — a resident prefix sentence must out-earn its cache cost; that arithmetic was itself priced in a currency #218/#220/#232 later inverted (a cache write costs under 1/3,462 of an output token on this plan), so declining twice on a superseded cost model is exactly what the elimination-context rule below exists to catch, turned on itself. _(validated ×5 — #195's inherited assumption gave way on measurement to #197/#198/#199; #207's threshold was re-measured rather than assumed; #209's slot-API arithmetic was declined once actually run; #210's fail-open `jq` was caught only by running it; #218's null result and #220's re-ranking were both found by measuring against this plan's own meter rather than trusting the inherited one.)_
- An elimination — or any inherited measurement or rationale — holds only in the context it was tested. Before inheriting or designing on one, check that context still applies: `skipLobby` sat on a closed issue's eliminated list, written off against a server whose mission was not initialised; against one that was, it worked first time. _(validated ×14 — newest five exemplars, the rest pruned to docs/process-log.md per #201: #157/#165: two closes in one cycle re-derived a filed premise rather than trusting it — #157's hand-maintained probe list defended itself with "these two are the corpus's contended leg" while four later issues had made it six, self-checking against a rename and blind to addition, fixed by deriving the list from the probe headers; and #165 re-read "run by nothing" against the tree, found `just spike` boots and `just build` packs the mission, and declined the asked-for deletion with the stay of execution recorded in the file's own header. #218/#220/#232: the token-efficiency corpus's whole ranking was an inherited measurement priced in list dollars, correct on an API key; re-measured against this plan's own meter the currency inverted it — output is on the order of a third of plan spend, not the 4.5% booked, and the cache-cliff family it ranked first-to-third is worth under 0.7% combined — so #232 re-based the ledger's spend column on the measured currency (`cap_fraction`, with its calibration named) rather than inheriting `cost_usd` as cost; the line's first application to a whole cost model rather than a single measurement. #239/#172: mutmut's filed verdict — incompatible with our pytest config — was re-run rather than inherited and failed both ways: the tool runs here (the "incompatibility" was `source_paths` naming a file, which unmade the `cti_daemon` package and let `-n auto` take the blame), and what it reports cannot carry a floor (its three survivors on a sound 75-line module were all equivalent mutants, so 62.5% on good tests is a floor a merely-running suite clears); the replacement gate was designed against the re-derived facts, not the filed verdict — the line's first application to a tool evaluation. #254: the filed diagnosis blamed hyphenated prose on the live bypass regex; replaying all three denied commands against `origin/main` showed none failed there, then isolated every denial to a stale pre-#167 hook copy whose unreadable branch had accused a bypass — the first whole defect report re-derived into a different bug before its fix. #90/#73/#215: three findings were bounded before work rather than inherited at face value — #90 established every caller before a rename batch and excluded an unrelated generic match; #73 found the filed daemon read-timeout already fixed at `3c1b9e0` and did not rebuild it; #215 found no header key absent from the docs, but the enforceable contract scattered across them and the runner — the first three applications in one cycle, across a caller set, a stale defect and a problem reclassified from absence to scatter.)_
- In any review pass, report everything you find; filtering by severity happens in a separate pass, not during the review.
- Match written documents to what the task needs — no filler sections, boilerplate, or redundant summaries. Lead every summary with the outcome.
- Land a convention together with its first applied instance; one living only in a design document is not yet a convention. Twice now: Phase 0's command table listed recipes that did not exist, and ADR-0016's probe headers sat on no probe for a day of corpus growth. _(validated ×5 — #23 landed the `just regress` table row, the lock, and the evidence conventions in the same commit as the recipe. #116 landed the vacuity rule's sentence in the same commit as its first instance — the client leg defaulted on, `unverified` in the verdict — after the tenth retro routed the adopted rule onto the fix by comment rather than landing it doc-first. #118 landed ADR-0041's locality convention, the macro pair, the lint, and the 19 guard deletions in one commit. #131: the fourteenth retro deferred the queue-clearing mechanism's doc sentence because the session was still running — no applied instance yet — and the fifteenth landed it once the first run completed, the rule operating as a reason to wait as well as to land. #208: the handoff-as-issue-comment template landed with itself as its first instance — the study's own handoff written to the template in the same commit — and #210 then landed the retrieval tool with the doc's pointer in the same commit, so the convention never told a successor to fetch something it did not say how to fetch.)_

**Human sign-off gates** — nothing lands on these without explicit approval: `CONTEXT.md` term changes; new or changed ADRs; acceptance spec changes; snapshot schema semantics; perceptual checklist growth; gameplay balance/feel decisions; changes to this file or the project skills.

Under the human's standing authorisation, an agent may take one of these decisions in their stead, but only by recording it in an ADR carrying the ADR-0013 marker, so `grep -rl "^Delegated-decision: yes" docs/adr/` answers "tell me every decision made on my behalf" completely. An unrecorded delegated decision is out of policy. The `.claude/settings.json` allowlist that pre-approves edits to these surfaces (#94, findings 13–16) is that standing authorisation's mechanical face, not a repeal of the gates: mechanical permission discharges nothing, and a gated change still lands only with the human's approval or an ADR-0013 record.

**ADR numbers are claimed, not assigned on write.** Agents run concurrently in separate worktrees, so two of them picking "the next free number" from the same `main` produce two ADR-00NNs — which happened on 2026-07-31 and cost a renumber. Before writing, `git fetch origin` and take the next number above every ADR on `origin/main` **and** every ADR number mentioned in an open issue comment; when landing, if the number collided, renumber yours as part of the rebase rather than leaving both. _(validated ×7 — newest five exemplars, the rest pruned to docs/process-log.md per #201: #35 claimed 0022 while the retro landed it, renumbered to 0023 before landing; #37's 0024 claim, posted on #35's thread, held. #49 wrote 0030 while #26's agent claimed it, found the collision on the rebase and landed as 0031, exactly as prescribed. The 0039→0040→0041 renumber chains: three concurrent landings in one cycle, the rule's heaviest concurrency yet, every collision found on the rebase and renumbered as prescribed — a central next-number file was weighed at the twelfth retro and declined, since a file every landing touches converts number collisions into merge conflicts whose resolution is the same renumber. #171 claimed 0048 with the prescribed scan honestly returning nothing — the competing claim sat on #168, which had closed ten minutes earlier, and the scan reads open issues — so the scan has a blind window when a claim's issue closes before its ADR lands; the rebase backstop caught it and #171 landed as 0049 with references updated, exactly as prescribed, which is why the window is recorded here rather than the scan widened. #182 claimed 0054 while the twenty-first retro's concurrent 0054 landed on #186's thread; found on the landing rebase, renumbered to 0055 with a fresh scan finding nothing above — exactly as prescribed.)_

## Agent skills

### Issue tracker

GitHub Issues on `andrewesweet/arma-cti` via `gh`. See `docs/agents/issue-tracker.md`.

### Triage labels

Default five-role vocabulary (`needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`, `wontfix`). See `docs/agents/triage-labels.md`.

### Domain docs

Single-context: root `CONTEXT.md` + `docs/adr/`. See `docs/agents/domain.md`.

### Interrupted-agent recovery

A dead agent resumes from its worktree under a two-sided resumption briefing; its leftovers are ADR-0022 stale infra. See `docs/agents/recovery.md` (ADR-0024).

### Orchestration seat

The orchestration seat's operating rules live in `docs/agents/orchestration.md`; read it before dispatching.

### Workflow backbone

Use the installed engineering skills rather than improvising process: `/implement` (+ `/tdd`, `/code-review`) for build work, `/research` for fact-finding (primary sources, cited, committed), `/prototype` for design questions, `/grill-me` for gameplay and design decisions that need human sign-off, `/diagnosing-bugs` for hard bugs, `/handoff` between sessions. Project-owned skills: `/interlocutor` (the human interface seat, opus/xhigh — ADR-0068), `/playtest-brief`, `/playtest-ingest`, `/retro`. Global skills are shared across projects — never edit them; project process learning lands only in this file, the project skills, and `docs/process-log.md`.
